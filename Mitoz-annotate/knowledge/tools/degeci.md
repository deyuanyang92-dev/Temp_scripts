## What it does
- De novo annotation of one metazoan mitogenome from its sequence alone: it looks up every 17-mer of the input in a de Bruijn graph built from all RefSeq mitogenomes, bridges gaps by local alignment, projects the annotations of the matching reference genomes onto the input, and clusters the votes into gene predictions. It uses no covariance models, no BLAST, no tRNA finder.
- Proteins, tRNAs and rRNAs are treated identically (a gene is a labelled interval in the reference annotations); the only gene-class-specific step is the optional start/stop codon correction, which applies to proteins only.

## Algorithm & key source locations
- Database: multigraph of all 8,015 metazoan mitogenomes of RefSeq 89 (RefSeq 204: 9,877 species), k = 16 so edges are 17-mers, each edge labelled genome, strand, position; stored in PostgreSQL, run with Apache Spark; reference annotations from the curated GenBank files normalised after Boore (2006) (doi:10.3389/fgene.2023.1250907)
- Pipeline of six stages: subgraph of the input's 17-mers, connected-component bridging by alternative trails, projection of database gene annotations, merging of fragments, clustering, bed output; the input must be a single sequence of at least 50 nt (DeGeCI-mapping/DeGeCI.java:51) (DeGeCI-mapping/DeGeCI.java:2742-2743) (doi:10.3389/fgene.2023.1250907)
- Bridging of unmapped stretches (poorly conserved regions, which is where divergent rRNA falls) looks for trails in the database between two seed hits and validates them with a local alignment, match +1 / mismatch -2 / gap -2, E-value <= 1e-3; a database with too little species diversity leaves large unmapped segments and slows the run (DeGeCI-mapping/DeGeCI.java:940-1155) (doi:10.3389/fgene.2023.1250907)
- rRNA ends: no rRNA-specific code. The input range of a mapped block is intersected with the reference gene interval and the overlap is shifted along the diagonal of the block (`s`, `e` on the input, `sref`, `eref` on the reference), so an end can only be as far as the mapped (conserved) block reaches; fragments of the same reference gene are then joined (DeGeCI-mapping/DeGeCI.java:566-608) (doi:10.3389/fgene.2023.1250907)
- Fragment joining, first stage: same gene, same strand, successor start within `maxD = 100` nt of the previous end (non-tRNA) or `maxDTrna = 40` (tRNA); the paper states "approximately 70 nt" (the length of the shortest typical gene) and the code passes 70 only to the wrap-around test, so paper and code differ (DeGeCI-mapping/DeGeCI.java:46-47) (DeGeCI-mapping/DeGeCI.java:1625) (DeGeCI-mapping/DeGeCI.java:1725-1728) (DeGeCI-mapping/DeGeCI.java:2880)
- Clustering: for each strand the database annotations at every input position are merged bottom-up into a tree; clusters whose normalised score is >= alpha (default 0.7) are reported, together with divergent sub-clusters; positions with more "no gene" votes than the two best genes, or with cumulative gene frequency < 0.8, are treated as unannotated; minimum number of database genomes predicting a gene `--count` 2; minimum edge weight `--weight` 1 (DeGeCI-mapping/Cluster.java:80-87) (DeGeCI-mapping/Cluster.java:375-407) (DeGeCI/code/src/main/java/de/uni_leipzig/informatik/pacosy/mitos/core/analysis/mapping/DeGeCIInputParser.java:67-81) (doi:10.3389/fgene.2023.1250907)
- Final length filter and second joining (applies to rRNAs too): per gene the mean length over all RefSeq genomes (`GENE_LENGTHS`, not taxon specific) gives `max = 1.5 x mean` and `min = 0.3 x mean`; two pieces of the same gene and strand are joined if the gap is <= 200 nt (non-tRNA) or 40 (tRNA) and piece1 + piece2 + gap <= max; across the circle origin the limit is 150 nt; every final prediction shorter than `min` is dropped (DeGeCI-mapping/DeGeCI.java:1462-1498) (DeGeCI-mapping/DeGeCI.java:1584) (DeGeCI-mapping/DeGeCI.java:2216-2218) (DeGeCI/code/src/main/java/de/uni_leipzig/informatik/pacosy/mitos/core/util/tools/DBCreator.java:422-432)
- Start/stop correction (version 1.1, optional `--trans-table` 1, 2, 4, 5, 9, 13 or 14): only for category "protein", searches up to `--shift` 6 nt each way for a start or stop codon, as MITOS2 does; rRNA and tRNA ends are not touched (DeGeCI-mapping/DeGeCI.java:2249) (DeGeCI-mapping/DeGeCI.java:2595) (DeGeCI/code/src/main/java/de/uni_leipzig/informatik/pacosy/mitos/core/analysis/mapping/DeGeCIInputParser.java:68-71) (doi:10.1093/bioadv/vbae072)
- Taxonomic filter (version 1.1): the user can restrict the reference genomes to a clade (`--taxonomic-groups`, `--taxids`) or exclude a clade (`--exclude-taxids`); the README example annotates a cnidarian with Cnidaria references only (DeGeCI/README.md:37-41) (DeGeCI/README.md:68-69) (doi:10.1093/bioadv/vbae072)
- Output: BED (end exclusive), gene-order text, FASTA of gene sequences, parameter file (DeGeCI/README.md:75-80)
- How the paper describes MITOS2: "Infernal in the glocal search mode"; the MITOS2 source read for tools/mitos2.md runs `cmsearch` in local mode unless `-g` is requested, so the paper's statement does not match the code we read (doi:10.3389/fgene.2023.1250907) (Mitoz-annotate/knowledge/tools/mitos2.md:28) (Mitoz-annotate/knowledge/tools/mitos2.md:52)

## Defaults that matter
- `--refseq 89`, `--alpha 0.7`, `--weight 1`, `--count 2`, `--shift 6`, `--treat-linear false` (input assumed circular), k = 16, `--trans-table` unset (no codon correction) (DeGeCI/code/src/main/java/de/uni_leipzig/informatik/pacosy/mitos/core/analysis/mapping/DeGeCIInputParser.java:67-81) (DeGeCI-mapping/DeGeCI.java:48-51)
- Increasing the edge weight lowers sensitivity and lengthens bridging; the authors report that the defaults gave good results for a broad spectrum of taxonomic lineages (doi:10.1093/bioadv/vbae072)
- Requirements: Java 8, Docker or a PostgreSQL server, Spark; database download 2.4 GB (RefSeq 89) or 2.7 GB (RefSeq 204), set-up "several hours" (DeGeCI/README.md:4-19) (doi:10.1093/bioadv/vbae072)

## Known bugs / issues
- Paper/code mismatch on the fragment-joining distance (70 nt in the paper; 100 nt for non-tRNA and 40 for tRNA in the first stage, 200 and 40 in the final stage in the code) (DeGeCI-mapping/DeGeCI.java:46-47) (DeGeCI-mapping/DeGeCI.java:1493) (doi:10.3389/fgene.2023.1250907)
- The final length window uses RefSeq-wide mean gene lengths, so a clade whose rRNA is much shorter or longer than the RefSeq mean can lose a correct prediction (below 0.3 x mean) or fail to merge pieces (above 1.5 x mean); not tested by the authors as far as the papers show (DeGeCI-mapping/DeGeCI.java:1463-1464) (DeGeCI-mapping/DeGeCI.java:1584) (未确证)
- Protein ends were "often slightly inaccurate" in version 1.0, which motivated the codon correction; no equivalent exists for rRNA (doi:10.1093/bioadv/vbae072)
- Optimised for complete mitogenomes; incomplete ones work but quality may suffer; not designed to detect misassembled mitogenomes; graphs from long-read data only may reduce quality because of higher error rates (doi:10.1093/bioadv/vbae072) (doi:10.3389/fgene.2023.1250907)
- Maintenance: last commit 2024-04-28, single author group, no licence file, no issue tracker activity visible (https://git.informatik.uni-leipzig.de/api/v4/projects/5811)

## Limitations by taxon
- Benchmark sample of 100 RefSeq 89 genomes: 32 Actinopterygii, 27 Arthropoda, 15 Mammalia, 13 Sauropsida, 7 Spiralia, 4 Amphibia, 2 non-bilaterians, chosen in proportion to RefSeq; none from Nematoda, Chaetognatha, Ctenophora, Placozoa, Acoela, Kinorhyncha or Tardigrada is listed, and the 2 non-bilaterians are not named in the text; each test genome's own edges were removed from the graph (doi:10.3389/fgene.2023.1250907)
- The per-taxon breakdown of rRNA accuracy is only in Supplementary Tables S1-S11 of the 2023 paper, which were not read (未确证)
- Seeds are exact 17-mer matches (k = 16); divergence beyond what 17-mers can seed leaves the segment to bridging, which needs seed hits on both sides; behaviour on rRNA from phyla absent or sparse in RefSeq 89 was not examined by the authors, and for the divergent phyla of interest to us it is 未确证 (doi:10.3389/fgene.2023.1250907)
- The authors state that, as for all database-based annotators, the database needs a certain minimum diversity of species or quality may be lower, and that RefSeq 39 (1,878 species) gave large unmapped regions and slow bridging, whereas RefSeq 204 removed two false negatives and one false positive of the sample (doi:10.3389/fgene.2023.1250907)

## Relevance to our pipeline
- DeGeCI is a reference-voting method; it needs RefSeq-scale data and a Spark/PostgreSQL stack, so we would not adopt it, but its evaluation protocol and its post-processing rules are reusable [inference]
- Numbers to compare against (RefSeq 89, 100-genome sample, own genome excluded, truth = RefSeq annotation): all 200 rRNAs found by both DeGeCI and MITOS2 with the right strand; share of rRNA predictions with both ends within 5 / 10 / 25 / 50 / 70 / 100 nt of RefSeq: DeGeCI 78 / 80 / 88 / 94 / 100 / 100 %, MITOS2 70 / 79 / 90 / 96 / 98 / 100 %; for comparison protein ends 85 / 94 / 97 / 99 % (DeGeCI) and tRNA ends 96 / 98 / 100 % (DeGeCI) within 5 / 10 / 25 nt. rRNA ends are therefore the weakest class for both tools, and about one fifth of rRNA ends differ from RefSeq by more than 5 nt even with a close reference [inference from Table 2] (doi:10.3389/fgene.2023.1250907)
- Idea 1 (scoring): report our rRNA end accuracy with the same cumulative curve (within 5 / 10 / 25 / 50 / 70 / 100 nt) and the same matching rule (RefSeq feature with the largest overlap, at least 75 % of the predicted positions shared; classes equal, different, strand difference, FP, FN) so that MitoM variants can be placed directly against these published MITOS2 / DeGeCI values [inference] (doi:10.3389/fgene.2023.1250907)
- Idea 2 (reuse the post-processing rules, no database needed): after cmsearch/MITOS2, (a) merge same-gene same-strand rRNA pieces when the gap is <= 100-200 nt and the merged length stays <= 1.5 x the clade mean; (b) drop or flag a final rRNA shorter than 0.3 x the clade mean; take the clade means from RefSeq per phylum instead of DeGeCI's RefSeq-wide mean, so that short nematode or tardigrade rRNAs and long cnidarian ones are not mis-judged [inference] (DeGeCI-mapping/DeGeCI.java:1462-1498)
- Idea 3 (clade-restricted reference, the DeGeCI taxonomic-filter idea): the MITOS2 rRNA models were built from RefSeq-wide alignments (about 7.9 k sequences, dominated by chordates and arthropods, see tools/mitopilot.md); for a missed phylum, build a small CM from the RefSeq rRNAs of that phylum (`cmbuild` on a MAFFT/R-scape-checked alignment) and run it alongside the stock model, as DeGeCI's gain from RefSeq 204 and from taxon-matched references suggests that closer references help [inference] (doi:10.1093/bioadv/vbae072)
- Idea 4 (end voting): DeGeCI sets an end from many references and keeps it only if a majority agrees (alpha 0.7); for MitoM, when a CM hit exists but the end is uncertain, project the end from several close RefSeq rRNAs through a pairwise alignment of the hit region and take the median, in place of snapping to the neighbouring gene; whether this beats neighbour snapping must be tested on the benchmark because DeGeCI itself gains only 8 points at <= 5 nt over MITOS2 [inference] (doi:10.3389/fgene.2023.1250907)
- Not applicable: the k-mer graph for divergent phyla (needs seeds), the Spark/PostgreSQL stack, the web server [inference]
