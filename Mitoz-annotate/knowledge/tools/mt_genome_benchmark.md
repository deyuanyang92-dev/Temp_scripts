## What it does
- A benchmark repository with two parts: `1_assembly` compares ten mitogenome assemblers on Illumina DNA and RNA reads of three Baikal amphipods; `2_annotation` compares annotation approaches on the finished mitogenomes. This note covers the annotation part and the rRNA results in it.
- Annotation approaches compared: MitoFinder (reference-based), MitoZ `annotate`, MITOS2 (two RefSeq reference sets), MFannot, AGORA, GeSeq, MitoFlex (one genome only), and raw covariance-model (CM) search for tRNAs with two CM sets (general RefSeq set and an amphipod-specific set) using the `competitive_mttrna_search` scripts.
- The comparison is a visual gene map of one genome (Eulimnogammarus cyaneus) against the RefSeq annotation moved onto the authors' own assembly; there is no numeric accuracy table in the repository.
- The authors' recommended practical procedure is: MitoFinder (assembly and annotation), then MITObim if no complete circular contig, then MITOS2 only if genes are missing after the MitoFinder annotation.
- An exploratory RNA-seq folder tries to predict mitochondrial RNA cleavage sites (poly-A and tRNA punctuation) from read alignments, using a published human method; it is not used to score the annotations.

## Defaults that matter
- Genetic code 5 (invertebrate mitochondrial) in every tool: MitoFinder `-o 5`, MITOS2 `-c 5`, MFannot and AGORA menus, GeSeq tRNA tools, MitoZ `genetic_code='5'` (mtbench/2_annotation/README.md:101) (mtbench/2_annotation/README.md:113) (mtbench/2_annotation/README.md:139-140) (mtbench/2_annotation/annotation_Mitoz/mitoz.log:10)
- The input is treated as circular only by some tools: the CM README tells users to append about 100 bases of the start to the end; GeSeq is set to "circular"; MitoFinder reported "Evidences of circularization could not be found" in all four logs, and MitoZ wrote `topology=linear` for the wo_NNN run, so a gene across the origin (here trnW) is split or lost (mtbench/2_annotation/README.md:10) (mtbench/2_annotation/README.md:134) (mtbench/2_annotation/annotation_Mitofinder/Mitofinder_Ecy_MitoFinder.log:25) (mtbench/2_annotation/annotation_Mitoz/annotation_Ecy_wo_NNN/tmp_Ecy_wo_OUR_mt_genom_Ecy.fasta_mitoscaf.fa/Ecy_wo_OUR_mt_genom_Ecy.fasta_mitoscaf.fa.l-rRNA.tbl:3)
- The MITOS2 reference set matters more than any parameter: refseq63m and refseq89m give a different rRNA on the same input (see Limitations), and the authors ran both because of that (mtbench/2_annotation/README.md:99) (mtbench/2_annotation/annotation_MITOS2/E_cyaneus_wo_NNN/refseq63/result.geneorder:2)
- The CM filter threshold used is bit score 20 with anticodon checking off; the README says each locus must then be inspected manually, so the tRNA result depends on a human step (mtbench/2_annotation/README.md:33-40)
- Reference choice dominates MitoFinder and AGORA/GeSeq results: a close reference (here the genome's own record) gives exact ends, a related-genus reference (Gammarus pisinnus, GeSeq/AGORA Gammarus) gives partial genes (mtbench/2_annotation/annotation.bed:63) (mtbench/2_annotation/annotation.bed:325)

## Relevance to our pipeline
- Evaluation design worth copying [inference]: take the finished RefSeq record of a species whose genome the authors re-assembled, move the truth by BLAST, and compare tools on the same input; but add what they lack: numeric end errors in nt per gene, overlap with neighbours, and a pass/fail per feature, so that results can be tabulated instead of read from a plot.
- Avoid their leakage [inference]: two of their strongest tracks (MitoFinder and AGORA "E. cyaneus") use the genome's own RefSeq as reference and are exact for that reason; our benchmark must exclude the test genome and its conspecifics from every reference or CM set, (no such exclusion could be confirmed in `benchmark/mito_bench_run.py` by a quick search for exclude/leak/self, 未确证, so check it).
- N-gap sensitivity test [inference]: their with/without-N pair shows rRNA calls change with a 68-N gap inside rrnL (MITOS2 and MitoFinder change, MitoZ does not); add a gapped variant (N run inside a rRNA and inside a PCG) to our benchmark sets and report it per tool.
- RNA-seq as an independent end truth for rRNA [inference]: their E. cyaneus coverage already discriminates the candidate ends (steps near 11182, 12096, 12788 versus MitoZ 12443 and 12945); build `rna-seq end` truth for any benchmark species that has same-specimen reads (their list has 79 E. cyaneus runs), call the 3' end of rrnL and rrnS as the coverage drop within 30 nt of the CM/tRNA-snapped end, and score the tools on it; this extends `topics/rrna_annotation_methods.md` section 5 rule on RNA-seq with a ready data set. The frame mismatch (14368 vs 14377 positions) must be solved first by re-mapping their reads ourselves.
- Competitive CM search for rRNA, not just tRNA [inference]: their raw refseq89m CM hits equal what MITOS2 sees (rrnL 11111-12263, rrnS 12188-12851), so the over-extension comes from the CMs and global alignment (the same signature as MitoZ's 1347-nt rrnL), not from MITOS2's selection logic; the anticodon-loop competition cannot be used for rRNA, but the same idea works with a different key: group hits by strand and overlapping coordinates, rank by bit score, and keep both rRNAs plus tRNAs in one non-overlap solution.
- tRNA-anchored clipping rule, prediction from their data [inference]: clipping the raw rrnL hit (11111-12263) to the interval between the end of trnL1 (11163) and the start of trnV (12143) gives exactly the moved RefSeq rrnL (11163-12143), and clipping rrnS (12188-12851) to start after trnV (12195) leaves +28 nt at the control-region side; this is testable in one script on their `annotation.bed` and on our own sets, and it would also restore tRNA-Val in the MitoZ case; it is a hypothesis, not a result.
- Do not rely on MITOS2 as the rRNA rescue [inference]: in their genome neither refseq63m nor refseq89m returns both rRNAs, so "fall back to MITOS2 if a gene is missing" would miss one rRNA in a clean genome; our `mito_curate.py` rule should read `ignored.mitos` for dropped rRNA candidates and re-test them with the tRNA clip above.
- Their tRNA competitive filter is a usable idea for `mito_trna.py` [inference]: group candidates by overlap of the anticodon loop rather than of the whole tRNA, take the best bit score, require the anticodon to be in the codon table; it needs the CM set per clade (their amphipod set recovers tRNA-Val and the general set does not), which matches our "clade CM versus universal CM" experiment.
- What not to copy [inference]: a single-genome visual comparison, hand inspection as the last step, and reference sets that include the target; also do not import the `--incE 0.05` global-mode settings without checking sensitivity on armless tRNAs.
- Open check before citing the paper [inference]: re-run the search for the published article (bioRxiv or journal) after a few weeks; the repository HEAD is dated 2026-10-14 and the article figures are final-looking (`fig05_ed.png`), so publication is probably near.
