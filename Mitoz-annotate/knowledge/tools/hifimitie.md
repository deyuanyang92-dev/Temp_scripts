## What it does
- Finds and assembles metazoan mitogenomes from PacBio HiFi reads: BLAST of reads against a local copy of the GenBank mito database, MiTFi for tRNAs, Infernal `cmsearch` for 12S/16S rRNA (and OL), BLAST for protein genes and OH, megahit and a MAFFT-consensus assembly, control-region (CR) tandem-repeat and heteroplasmy analysis.
- The rRNA step is a locator, not a boundary-refinement step: it runs one `cmsearch` per rRNA model on every HiFi read and on each assembled mitogenome, and writes the first hit of each sequence into the annotation table as an `rrnS` / `rrnL` row with the hit's coordinates unchanged.
- The rRNA rows give the gene order of each read (so the F-rrnS-V-rrnL... template can be checked) and serve as flanks of the control region when 12S is the neighbour (arthropods).

## Algorithm & key source locations
- rRNA search = exactly one `cmsearch` command per model, run on a multi-FASTA: `cmsearch --noF4b --cpu $threads --notextw -E 0.01 --mxsize 80000 --tblout <x>.tbl <model> <fasta> > <x>.cmout`, models `models/rrnS.cm` and `models/rrnL.cm`, always local mode (no `-g`) (HiFiMiTie/script/rrna_cmsearch.sh:28-29) (HiFiMiTie/script/rrna_cmsearch.sh:70)
- The script header says v2 uses "rrnS.cm and rrnL.cm instead of 12S_s-rna.cm and 16S_l-rna.cm", "mitos2 style args", and "always do local search not global"; the comment at the command says the settings "were determined by looking at the mitos2 cmout output files" (HiFiMiTie/script/rrna_cmsearch.sh:3-5) (HiFiMiTie/script/rrna_cmsearch.sh:69)
- Callers: step 6 on all candidate HiFi reads (`mito_hifi_recs.fasta`), the megahit contig, and the MSA consensus (HiFiMiTie/script/06_rna_search.sh:31) (HiFiMiTie/script/assemble_w_megahit.sh:110) (HiFiMiTie/script/assemble_w_mafft_and_consensus.sh:194)
- Table to annotation row (`add_rrna_to_mitfi.sh`): for each target sequence only the first non-comment row of the .tbl is kept (`!($1 in S_ar)`); seq from / seq to are swapped if reversed; the row is written as start, end, score, E-value, `complete` or `<trunc>_trunc`, symbol (the CM name, i.e. rrnS / rrnL), model label, strand (HiFiMiTie/script/add_rrna_to_mitfi.sh:24-31)
- No merging of several hits of one model, no trimming, no extension towards neighbouring genes: the cmsearch coordinates are used as they are, also in the GFF export (HiFiMiTie/script/add_rrna_to_mitfi.sh:27-29) (HiFiMiTie/script/convert_hfmt_anno_to_gff.sh:49-52)
- Truncation flag: tblout column 11 (`trunc`, values `no`, `5'`, `3'`, `5'&3'`) becomes `complete` or `5'_trunc` etc., so a read that ends inside rRNA is marked; an rRNA hit that lies after the last tRNA of the read is written at the end of that read's block (HiFiMiTie/script/add_rrna_to_mitfi.sh:26) (HiFiMiTie/script/add_rrna_to_mitfi.sh:42-45) (HiFiMiTie/script/add_rrna_to_mitfi.sh:60-64)
- Position in the table: the rRNA row is inserted before the first MiTFi tRNA row whose start is greater than the rRNA start (HiFiMiTie/script/add_rrna_to_mitfi.sh:49-56)
- Second filter: when building the per-read one-line order summary, features with E-value > 0.001 are dropped, stricter than the `-E 0.01` of the search (HiFiMiTie/script/one_liner_per_cm_anno_rec.sh:136)
- 12S can be the flank of the control region: `first_rna` / `last_rna` are read from the first / last item of the right-neighbour matrix, and the CR flanks may be "12S", written 2023-01-03 for arthropods (HiFiMiTie/script/06_rna_search.sh:274-304) (HiFiMiTie/script/add_CR_to_mitfi.sh:41)
- Models are Bernt's MITOS covariance models: `rrnS.cm` (CLEN 899, NSEQ 3825, built 2018-06-02 with Infernal 1.1.2 from `metazoa/cleaned/rrnS.stk`) and `rrnL.cm` (CLEN 1561, NSEQ 3836, built 2018-06-02); the retired v1 models `12S_s-rna.cm` (CLEN 952, NSEQ 1307, 2010) and `16S_l-rna.cm` (CLEN 1630, NSEQ 1183, 2010) are still in `models/` (HiFiMiTie/models/rrnS.cm:2-11) (HiFiMiTie/models/rrnS.cm:22) (HiFiMiTie/models/rrnL.cm:5) (HiFiMiTie/models/rrnL.cm:22) (HiFiMiTie/models/12S_s-rna.cm:5) (HiFiMiTie/models/16S_l-rna.cm:24)

## Defaults that matter
- `-E 0.01`, `--noF4b` (turns off the glocal Forward composition-bias filter, per Infernal 1.1.5 `cmsearch --devhelp`, our run), `--notextw`, `--mxsize 80000`, local mode, `--cpu` = the `-t` thread value of the run (default 1 inside the script; README says the pipeline default is 32 threads) (HiFiMiTie/script/rrna_cmsearch.sh:58-60) (HiFiMiTie/script/rrna_cmsearch.sh:70) (HiFiMiTie/README.md:32)
- `--mxsize` is not the option MITOS2 uses: MITOS2 passes `--smxsize 80000` (search DP matrix limit), whereas Infernal 1.1.5 `cmsearch -h` documents `--mxsize` as "max allowed alnment mx size" (auto-determined) and `--smxsize` as "max allowed size of search DP matrices" [128 Mb]; the HiFiMiTie comment calls its settings "mitos2 style"; effect on results 未确证 [our run: `cmsearch -h` of the mitos env] (Mitoz-annotate/knowledge/tools/mitos2.md:28) (HiFiMiTie/script/rrna_cmsearch.sh:4)
- Only the E-value (`-E 0.01`) decides whether a hit is reported; no minimum length, no minimum model coverage (mdl from / mdl to are never read) (HiFiMiTie/script/add_rrna_to_mitfi.sh:24-29)
- Site-specific settings: the mito database path, taxonomy dump and several scripts point to `/ccg/...` on the authors' cluster (HiFiMiTie/system_settings.tsv:4-6) (HiFiMiTie/script/mito_pcg_anno.sh:57)

## Known bugs / issues
- Only the first .tbl row per target sequence is used; whether this is the best-scoring hit depends on cmsearch writing hits in score order, which was not checked; a second rRNA copy on the same read is ignored (HiFiMiTie/script/add_rrna_to_mitfi.sh:24) (未确证)
- The label (12S vs 16S) is chosen by testing the table file name for an upper-case `L` (`$1 ~ "L"`), so any `L` in the path given to the script (`.../Lxxx/rrna_rrnS.tbl`) would make 12S rows read as 16S; read in code, not run (HiFiMiTie/script/add_rrna_to_mitfi.sh:20)
- `have_tbl_hit` tests `[ ln3_ch == "#" ]` without `$`, so it can never be false for an existing file; in v1 the "global first, local if empty" fallback therefore never ran after a global search that wrote a header-only table; the function is still defined in v2 but its only use is commented out (HiFiMiTie/script/bup/v1_rrna_cmsearch.sh:44-46) (HiFiMiTie/script/bup/v1_rrna_cmsearch.sh:57) (HiFiMiTie/script/rrna_cmsearch.sh:48-50) (HiFiMiTie/script/rrna_cmsearch.sh:67)
- OH BLAST hits "hovering over 12S" had to be removed with a score cut-off (`min_score_for_OH=225`), described by the author as "kludgy"; rRNA rows overlapping OH look-alikes are therefore a known source of false features (HiFiMiTie/script/add_OH_to_mitfi.sh:8)
- Maintenance: last commit 2024-08, single author group, no issues filed, no tests directory (https://github.com/calacademy-research/HiFiMiTie)

## Limitations by taxon
- Written for metazoan HiFi data and developed on a fish mitogenome with unusual tRNA order and CR heteroplasmy; the README tabulates first-tRNA statistics for vertebrates and Lepidoptera only (HiFiMiTie/README.md:2) (HiFiMiTie/README.md:10) (HiFiMiTie/README.md:100-101)
- Only the two MITOS metazoan rRNA models (and their 2010 predecessors) are shipped; no taxon-specific or divergent-phylum rRNA model exists in `models/`, so a phylum whose rRNA the MITOS models do not match (Chaetognatha, Ctenophora, Placozoa, Acoela, Kinorhyncha, Nematoda, Tardigrada) is not addressed by the tool; behaviour on those phyla was not tested by the authors as far as the repository shows (HiFiMiTie/models/rrnS.cm:2) (未确证)
- The tool depends on the MiTFi tRNA order and on a close mitogenome in GenBank as seed (reads are first selected by BLAST to the mito database); for a phylum without relatives in the database the read pull may fail before the rRNA step is reached (HiFiMiTie/README.md:36-38)

## Relevance to our pipeline
- Closest published precedent for MitoM's rRNA step: HiFiMiTie also calls MITOS Infernal `rrnS.cm` / `rrnL.cm` with `-E 0.01` and takes the hit coordinates; the difference is that it does not trim or extend, so it offers no help for ends [inference]
- Idea 1: test local versus global (`-g`) search of the rrnS/rrnL models on the divergent-phylum genomes where MitoM finds no rRNA. HiFiMiTie's own comparison shows global search gives far weaker E-values for the same hit and a spurious 5'-truncated fragment, which is also how a "split into short pieces" result can arise; MitoZ's rRNA step is the same design as HiFiMiTie v1 (`cmsearch -g` with the 2010 MITOS v1 models CLEN 952/1630, local only if the global table is empty), the arrangement HiFiMiTie replaced. Run `cmsearch --noF4b -E 0.01` local plus `--max` on the missed genomes and score against RefSeq rRNA [inference] (Mitoz-annotate/knowledge/tools/mitoz.md:34)
- Idea 2: use the tblout columns that HiFiMiTie ignores (mdl from, mdl to, trunc) to compute model coverage of each hit (model span / CLEN 899 or 1561). A hit covering < ~50 % of the model is a fragment; fragments of the same model on the same strand that are collinear in model coordinates and close in the genome can be merged into one rRNA, and the missing model 5'/3' length gives an expected extension, clamped at the neighbouring gene [inference]
- Idea 3: evaluate both CM generations (HiFiMiTie June-2018 models trained on about 3.8 k sequences versus refseq89m Aug-2018 models trained on about 7.9 k sequences, CLEN 899/1561 versus 894/1537) on the divergent phyla and take the best-scoring hit per locus; the older set is only available from this repository, provenance 未确证 [inference] (HiFiMiTie/models/rrnS.cm:22) (refseq89m/ncRNA/rrnS.cm:22)
- Idea 4: keep the "complete / 5'_trunc / 3'_trunc" status of each rRNA in our output so that curation (mito_curate R1) extends only rRNAs that are flagged truncated or fragmentary, not those with full model coverage [inference]
- Not usable: reads-based seeding by BLAST to a close relative, the `/ccg` paths, and the one-line-per-read order summary (we annotate finished genomes) [inference]
