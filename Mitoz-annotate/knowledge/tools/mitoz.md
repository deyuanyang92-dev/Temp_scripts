## What it does
- `mitoz annotate` takes one or more finished mitogenome FASTA files and writes a GenBank file (.gbf), a 5-column feature table (.tbl), `summary.txt`, per-gene FASTAs and a circos plot. PCGs come from homology search against a clade protein database, tRNAs from MiTFi, rRNAs from Infernal covariance models, a putative control region from the leftover gap, and tbl2asn assembles the record.

## Algorithm & key source locations
- Driver: per FASTA record the header is rewritten as `>id topology=...` (default `topology=linear` if absent), then in order CDS (line 658), tRNA (666), rRNA (672), combine and tbl2asn (680), gene extraction (697), circos (702) (mitoz/annotate/annotation.py:617-711)
- Sequence ids longer than 13 characters are refused; ids with `;`, `(`, `)` made genewise unable to read the temp FASTA (mitoz/annotate/annotation.py:649-651) (https://github.com/linzhi2013/MitoZ/issues/37)
- PCG search: `tblastn -evalue 1e-5 -seg no -db_gencode <code>`, query = clade protein DB, subject = the genome; hits with identity <= 30 % dropped (mitoz/annotate/script/MT_annotation_BGI_V1.32/MT_annotation_BGI.pl:145) (mitoz/annotate/script/MT_annotation_BGI_V1.32/MT_annotation_BGI.pl:283)
- SOLAR joins HSPs; a hit is kept only if SOLAR score >= 25 and the aligned part covers >= 25 % of the query protein; every extra hit of the same query becomes a `-D<n>` copy (mitoz/annotate/script/MT_annotation_BGI_V1.32/MT_annotation_BGI.pl:300-326)
- Redundant loci are collapsed when two hits overlap by >= 50 % of the shorter one (mitoz/annotate/script/MT_annotation_BGI_V1.32/genomic_cluster.pl:8)
- GeneWise is run on the hit region extended by 2000 nt each side (clipped at the sequence ends, no wrap-around), strand forced from the hit (`-tfor`/`-trev`), options `-genesf -gff -sum` (mitoz/annotate/script/MT_annotation_BGI_V1.32/MT_annotation_BGI.pl:426-465)
- GeneWise always uses the fixed table `codon_InverMito.table` (TAA/TAG = X, TGA = W, ATA = M, AGA/AGG = S) whatever `--genetic_code` is, only tblastn gets the real code; for code 2 (Chordata, AGA/AGG stops) and code 9 (AAA = N) this is a mismatch whose effect on boundaries is 未确证 (mitoz/annotate/script/MT_annotation_BGI_V1.32/codon_InverMito.table:13-50)
- Multi-exon GeneWise models are collapsed to one span `first exon start : last exon end`; the CDS feature table then writes a single interval, so MitoZ cannot write a `join(...)` CDS and has no intron handling (no occurrence of "intron" in the package .py files) (mitoz/annotate/script/MT_annotation_BGI_V1.32/getGene.pl:48) (mitoz/annotate/script/cds_ft_v2.py:85-87)
- Reference protein headers must look like `gi_<id>_<GENE>_<species>_<n>_aa`; the pipeline appends `_Ref<query start>:<query end>aa` (add_protein_position.pl) and a regex then reads gene, aa length, reference start/end and `locus=<seq>:<start>:<end>:<strand>`; a header that does not match is only printed as "can not match" and the gene is lost; `Ref<start>` later sets the start-codon search depth (mitoz/annotate/script/MT_annotation_BGI_V1.32/add_protein_position.pl:10) (mitoz/annotate/script/prepare_CDSposition.py:49-66)
- Stop codon search, per gene, `revise_CDS_pos_v6.py`: first look 1 to 9 codons downstream of the GeneWise end for the first in-frame complete stop (translated with the real table); only if none is found, test for a lone `TA` then `T` at codon steps 0..9 after the end and add the note "TAA stop codon is completed by the addition of 3' Aresidues to the mRNA"; if still nothing, the end is written as `>end` (partial) (mitoz/annotate/script/revise_CDS_pos_v6.py:113-203)
- Start codon search: for j = 0..(ref_start+10) codons upstream of the GeneWise start, translate window `[start-3j, GeneWise start+21)` plus an appended TAG with Biopython `cds=True` (falls back to `cds=False` on error); accept the first j whose protein begins with M and has <= 1 stop; this accepts the GeneWise start itself if it is a valid start, otherwise the NEAREST valid upstream start, not the longest ORF (mitoz/annotate/script/revise_CDS_pos_v6.py:221-259)
- Biopython `cds=True` turns the table's alternative start codons (code 5: TTG, ATT, ATC, ATA, GTG; code 2: ATT, ATC, ATA, GTG; code 9: GTG) into M only when the window has no internal stop; with an internal stop the code falls back to `cds=False`, where they translate as L/I/V and are rejected (checked with Biopython 1.83, e.g. ATTCCCAAATAG gives MPK but ATTCCCTAATAG gives IP**) (mitoz/annotate/script/revise_CDS_pos_v6.py:241-246)
- If no upstream start works, up to 10 codons DOWNSTREAM of the GeneWise start are tried (start moves inward); if still none the start is written `<pos` with note "can not determine the start codon" (mitoz/annotate/script/revise_CDS_pos_v6.py:262-308)
- After revision, genes with several loci are filtered: a lower-scoring copy survives only if its length is > 0.8 of the longest copy, so near-equal duplicates are all written under the same gene name (mitoz/annotate/annotation.py:211-220) (mitoz/annotate/script/filter_cds_by_annotated-len.py:70-72)
- CDS feature table: each gene gets a `gene` and a `CDS` row (minus strand swapped), `product` from a fixed 13-name dictionary (KeyError for any other name), `transl_table`, optional `note` (mitoz/annotate/script/cds_ft_v2.py:43-95)
- tRNA: one MiTFi call per sequence (details in tools/mitfi.md), results turned into `trn<AA>(<anticodon>)` with `tRNA-<Name>` products (mitoz/annotate/annotation.py:257-291)
- rRNA: `cmsearch -g` (glocal) against `v1.1_12snew.cm` (CLEN 952) and `v1.1_16snew.cm` (CLEN 1630); only if the global tblout is empty is a local search repeated; the same two models are used for every clade (mitoz/annotate/annotation.py:322-341) (mitoz/annotate/annotation.py:595-596)
- rRNA hit filter: only `!` hits (Infernal default inclusion E-value 0.01), aligned length > 100 nt; a second hit on the same sequence is accepted only if its start is >= 5000 nt from the first, otherwise reading stops; coordinates are taken straight from cmsearch (mitoz/annotate/script/rRNA_ft.py:68-109)
- Global mode aligns the whole model, so rRNA ends follow the model termini and not the real gene ends: in a local test run on NC_015609.1 (Arthropoda, scratch files, not persisted) the 16S hit used model columns 1..1630 over 1338 nt (13989..12652) and overlapped trnL(uag) by 23 nt and trnV by 2 nt; the 12S hit (14841..14058) overlapped trnV by 2 nt (/tmp/claude-0/-mnt-n-yzz------/934ca37c-5895-4358-b309-900011b04d11/scratchpad/mitoz_kb/ma/w/tmp_t_lib.fasta_mitoscaf.fa/t_lib.fasta_mitoscaf.fa.l-rRNA.tbl:3)
- Combine: feature tables of the four classes are concatenated per sequence; missing classes only print a message; the run exits only if all four are empty (mitoz/annotate/annotation.py:405-439)
- Control region (`misc_feature`, note "putative control region") is attempted only if CDS, tRNA, 12S and 16S tables are all non-empty and the sequence has >= 13 PCGs at least as long as the clade length list, 22 distinct `trn...` names and two rRNAs >= 0.9 x model length; the longest uncovered gap >= 600 nt is reported (circular genomes join the two ends) (mitoz/annotate/annotation.py:444-457) (mitoz/annotate/script/find_contro_region.py:118-176) (mitoz/annotate/script/find_contro_region.py:220-247)
- The PCG length cutoff in the control-region script ignores its ratio argument (`ratio` is never used), so the full listed length is required although 0.9 is passed (mitoz/annotate/script/find_contro_region.py:77-88)
- The FASTA gets `[organism=...] [topology=...] [mgcode=<table>] [location=mitochondrion]`; then `tbl2asn -t template.sbt -a s -p . -V vb` writes the .gbf and the .val validation (mitoz/annotate/script/prepare_fsa.py:48-58) (mitoz/annotate/annotation.py:462-479)
- `topology` is read only for the FASTA defline `[topology=]`, the control-region gap joining and the `Circularity` column of summary.txt; CDS, tRNA and rRNA search treat every sequence as linear, so a gene across the origin is cut in two and reported without stop/start (mitoz/annotate/script/prepare_fsa.py:55-58) (mitoz/annotate/script/find_contro_region.py:182-189) (mitoz/annotate/script/revise_CDS_pos_v6.py:113-120)
- `summary.txt` writer adds 1 to both start and end although the Biopython end is already inclusive; verified on a test run where the .gbf/.tbl give trnI 1..66 and ND2 268..1281 but summary.txt gives 1..67 and 268..1282 (mitoz/annotate/script/genbank_gene_stat_v2.py:52-80)

## Defaults that matter
- `--clade` default Arthropoda, allowed Chordata, Arthropoda, Echinodermata, Annelida-segmented-worms, Bryozoa, Mollusca, Nematoda, Nemertea-ribbon-worms, Porifera-sponges (mitoz/annotate/annotation.py:82-88)
- `--genetic_code auto` maps clade to table: Chordata 2, Arthropoda 5, Echinodermata 9, Annelida 5, Bryozoa 5, Mollusca 5, Nematoda 5, Nemertea 5, Porifera 4 (mitoz/annotate/annotation.py:561-567)
- `--thread_number` default 8; two users saw fewer genes with more threads and one fixed it with 1 thread, cause not shown by the maintainer (https://github.com/linzhi2013/MitoZ/issues/131) (https://github.com/linzhi2013/MitoZ/issues/80)
- Reference protein sets are small for worms: Annelida 964 proteins (about 74 per gene, ND6 68), Nemertea 218, Bryozoa 89, versus Arthropoda 22 469 and Chordata 56 301 (counted with `grep -c '>'`) (mitoz/profiles/MT_database/record.sh:5-17)
- Length list for Annelida (bp, used only for control-region logic): ATP6 498, ATP8 148, COX1 1532, COX2 639, COX3 700, CYTB 1048, ND1 874, ND2 906, ND3 330, ND4 1134, ND4L 246, ND5 1425, ND6 435 (mitoz/profiles/CDS_HMM/Annelida-segmented-worms_CDS_length_list:1-13)
- MiTFi flags `-evalue 0.001 -onlycutoff -cores 1`, rRNA `cmsearch -g`, control region 600 nt / 0.9 / 22 tRNAs (mitoz/annotate/annotation.py:274-278) (mitoz/annotate/annotation.py:444-457)
- Stop search window 9 codons, start search window ref_start + 10 codons, T/TA test only after the complete-stop search failed (mitoz/annotate/script/revise_CDS_pos_v6.py:113-153)

## Known bugs / issues
- Greedy stop extension: a CDS that truly ends in T/TA is extended up to 27 nt into the next gene when an in-frame stop exists downstream (example: COX2 of NC_030597, aligned to 7895, written to 7916, into trnK; reporter sees this often in ~800 fish genomes); maintainer agrees it is greedy and suggested constraining PCGs by tRNA boundaries or an option to switch it off (open) (https://github.com/linzhi2013/MitoZ/issues/175)
- Longer-than-published ND1/ND4/12S on the N-strand, with ND1 covering all of trnS; maintainer's explanation: an internal stop in the genome makes the stop search fall through to the T/TA 3' extension, and tRNA calls come from MiTFi (closed) (https://github.com/linzhi2013/MitoZ/issues/146)
- Start codon: MitoZ searches upstream and stops at the first start codon found, so a reference protein whose own annotation starts late pins the start late; maintainer's note says reference annotations may themselves be wrong and he did not adopt "extend as far as possible" (open) (https://github.com/linzhi2013/MitoZ/issues/31)
- Genes crossing the sequence origin are annotated only in part (missing stop/start); remedy is to re-break the circular genome in a gene-free region and re-run annotate (https://github.com/linzhi2013/MitoZ/issues/75) (https://github.com/linzhi2013/MitoZ/issues/173) (https://github.com/linzhi2013/MitoZ/wiki/Known-issues)
- Alternative start codons are shown as M in the GenBank translation (COX1 starting GTG in tilapia), which users read as a mistranslation; maintainer only pointed to the NCBI genetic-code table (https://github.com/linzhi2013/MitoZ/issues/230)
- Clades whose protein files ship in the package (Cnidaria, Platyhelminthes, Chaetognatha) cannot be selected: `--clade` has no such choice and CDS_HMM lacks the HMM and length list; workaround is a custom `--profiles_dir` with the three files for an existing clade name (open) (https://github.com/linzhi2013/MitoZ/issues/181) (https://github.com/linzhi2013/MitoZ/issues/221) (https://github.com/linzhi2013/MitoZ/issues/182)
- Custom or extended protein DB must use the exact `gi_NC_<acc without .1>_<GENE>_<Genus_species>_<len>_aa` header and the 13 uppercase gene names; otherwise "regular match fails" and no PCG is annotated (https://github.com/linzhi2013/MitoZ/issues/227) (https://github.com/linzhi2013/MitoZ/wiki/Extending-MitoZ-s-database)
- Warnings "name gi_..._ATP6_... is not uniq" come from duplicate ids inside the shipped DB; maintainer: harmless (https://github.com/linzhi2013/MitoZ/issues/38)
- tRNA step fails silently when the bundled `cmsearch.linux` cannot run: no tRNAs and doubled/split 12S (fixed for the Docker image in release 3.6, but conda users still hit it) (https://github.com/linzhi2013/MitoZ/issues/187) (https://github.com/linzhi2013/MitoZ/issues/208) (https://github.com/linzhi2013/MitoZ/issues/225)
- Control region shorter than 600 nt is never reported; maintainer offered an option but the issue is still open (https://github.com/linzhi2013/MitoZ/issues/198)
- Missing genes after install problems (wrong conda env, ete3 taxonomy DB) look like annotation failures; the author reproduced perfect annotations with the Docker image for the same sequences (https://github.com/linzhi2013/MitoZ/issues/89) (https://github.com/linzhi2013/MitoZ/issues/84)
- `tbl2asn` older than one year may refuse to run, giving no .gbf and a crash in the summary step; update tbl2asn (worked in this env on 2026-10-20) (https://github.com/linzhi2013/MitoZ/issues/113)
- tbl2asn messages from MitoZ output: partial or T/TA-completed stops with only a `note` are reported `SEQ_FEAT.NoStop` (ERROR) (test run NC_015609.1: COX2 and ND5 NoStop) (https://github.com/linzhi2013/MitoZ/wiki/Tutorial)

## Limitations by taxon
- Only nine clades have HMM + protein DB + length list; others must borrow a clade and a table, e.g. Cnidaria needs a custom profile directory (https://github.com/linzhi2013/MitoZ/wiki/FAQ)
- ATP8 is "very divergent for some clades" and often missed with the shipped DB; the fix is to add one close relative's protein to the clade file (https://github.com/linzhi2013/MitoZ/wiki/New-Features)
- Vertebrate (code 2) genes ending in AGA/AGG: GeneWise treats them as Ser, real stop found only by the later 9-codon search (inference from the fixed table); effect 未确证 (mitoz/annotate/script/MT_annotation_BGI_V1.32/codon_InverMito.table:47-50)
- tRNA losses and truncated tRNAs in basal Metazoa, Arthropoda (spiders), Nematoda lower MiTFi recall (doi:10.1093/nar/gkr1131) (https://github.com/linzhi2013/MitoZ/issues/74)
- Marsupials with non-standard tRNA-Asp anticodon (GCC) get a second Gly instead (https://github.com/linzhi2013/MitoZ/issues/237)
- NCBI lists Cnidaria and Porifera as exceptions to "13 CDS, 22 tRNA, 2 rRNA", so MitoZ's 22-tRNA gate for the control region never fires there (https://www.ncbi.nlm.nih.gov/genbank/organelle_submit/)
- Mitochondrial genomes with introns inside PCGs (for example group I/II introns): no support, MitoZ writes a CDS as one continuous interval (mitoz/annotate/script/cds_ft_v2.py:85-87)
- Linear mitogenomes: header `topology=linear` is honoured only for control region; genes at both ends can lose start/stop (mitoz/annotate/annotation.py:641-654)

## Relevance to our pipeline
- `batch_mitoz.py` should always pass the clade and `--genetic_code` explicitly (annelids: Annelida-segmented-worms, 5) and write `topology=circular|linear` and ids <= 13 characters without `;()` before calling annotate; otherwise MitoZ silently treats the genome as linear Arthropoda.
- Reorienting to cox1 start before annotation is useful because MitoZ cannot annotate across the origin; the new origin should be placed in a non-coding stretch, as the MitoZ wiki advises for broken genes.
- `mito_curate.py` P1/P3/R1 exist because of MitoZ behaviours listed above: nearest-upstream start, greedy complete-stop search before T/TA (issue 175), full-model rRNA ends overlapping tRNAs; the pipeline README measured 126 of 128 table2asn errors as NoStop on MitoZ output, consistent with note-only T/TA stops (temp_scripts/Mitoz-annotate/README.md:632).
- `mito_intron.py` is required because MitoZ never writes `join()` CDS; run it after curation, and expect MitoZ to place a CDS span over, or truncated at, an intron.
- MiTFi speed and recall: `scripts/mitoz_fast.py` and `mito_trna.py` replace/extend MiTFi; see tools/mitfi.md.
- Do not parse `summary.txt` coordinates (end and length are +1); use the .gbf or .tbl.
- Gene names in MitoZ output are `ND1`, `COX1`, `l-rRNA`, `s-rRNA`, `trnL(uaa)` (RNA letters); normalise before comparing with GenBank references.
