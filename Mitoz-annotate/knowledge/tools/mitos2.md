## What it does
- Annotates metazoan mitochondrial genomes de novo: 13 protein-coding genes by BLASTX against RefSeq protein families, tRNAs (22), rRNAs (rrnS, rrnL), OL and group I/II introns by Infernal covariance models, OH by BLASTN.
- tRNA step = Infernal `cmsearch` per tRNA model, post-processed by the closed-source Java program MiTFi, which chooses the tRNA identity from the anticodon, not from the model.
- Writes `result.bed`/`result.gff`/`result.seq`/`result.mitos`; weaker or conflicting hits go to `ignored.mitos`.

## Algorithm & key source locations
- Entry point `runmitos`; `mitos()` runs for a circular input on two rotations (offset circrot and circrot+180 degrees), searches both, and maps hits back modulo the length (mitos/scripts/runmitos.py:185-190) (mitos/mitfi/__init__.py:340-344)
- Order of work: RNA models first (fast pass), optional sensitive re-search, then BLAST proteins, then OH, then merge into one conflict-free feature list (mitos/scripts/runmitos.py:255-306)
- RNA search: one `cmsearch` per model file in `refdir/ncRNA/*.cm`; model-file prefix decides the class (`rrn*`, `trn*`, `OL*`, `Intron*`); the generic `tRNA.cm` matches none of these and is skipped (mitos/mitfi/__init__.py:124-168)
- cmsearch command: `cmsearch --cpu 1 --notextw --smxsize 80000 [--noF4b] -E <evalue> [-g] model seq`; `--noF4b` only in fast mode, `-g` (glocal) only if glocal mode is requested, otherwise local mode (mitos/mitfi/__init__.py:81-90) (mitos/mitfi/__init__.py:101) (mitos/mitfi/__init__.py:117-121)
- Fast pass E-value is `--ncev` (CLI default 0.01, not the 0.001 of the function signature); cmsearch `-E` and MiTFi `-evalue` get the same value (mitos/scripts/runmitos.py:1259-1264) (mitos/scripts/runmitos.py:59) (mitos/scripts/runmitos.py:264) (mitos/mitfi/__init__.py:101) (mitos/mitfi/__init__.py:112-113)
- Sensitive fallback: runs when `--sensitive` is set or when `mitfi.remove_empty(...)` is true; it re-runs cmsearch with `-E 0.1` and `--max` for tRNA models (rRNA: `--nohmm`) whose fast-pass output was deleted (mitos/scripts/runmitos.py:275-298) (mitos/mitfi/__init__.py:153-157)
- `remove_empty` deletes the cmsearch output of every tRNA model whose name is absent from the result list (a "missing" tRNA such as trnS1), unless that file is already sensitive-mode; it also deletes the MiTFi `*out.nc` files and returns True whenever such a file existed, so the MiTFi step is always repeated; observed 2026-10-20 on NC_000931 (22 tRNAs found): 0 `--max` calls but 4 MiTFi calls (2 rotations x 2 passes) (mitos/mitfi/__init__.py:350-406)
- Consequence for tRNA-poor genomes (anthozoans, sponges): every tRNA model without a hit is searched again with `--max` at E <= 0.1, and hits with E up to 0.1 become first-round best hits; observed 2026-10-20 on NC_006902 (Montipora cactus, 2 RefSeq tRNAs): fast mode 5 s and 2 tRNAs (trnM, trnW, boundaries identical to RefSeq); full mode 643 s (40 sensitive cmsearch calls = 20 models x 2 rotations) and 4 tRNAs, the extra trnF(aaa) E=0.065 and trnL2(caa) E=0.041 (bit scores 18.0 and 16.3) are not in RefSeq; on NC_000931 (22 tRNAs) fast and full gave identical results in 8 s each (mitos/scripts/runmitos.py:275-298) (mitos/mitfi/__init__.py:153-157)
- MiTFi call: `java -jar mitfi_import.jar -code <table> -codefile mitfiGeneticCodes -structure -genome seq -glength L -evalue E -method l|g -overlap 50 -in <model>.cmout ...`; `-overlap` = `--maxtrnaovl` (default 50 nt); the jar contains only compiled classes (Main, tRNA), no source (mitos/mitfi/__init__.py:96-114) (mitos/mitfi/__init__.py:142) (mitos/scripts/runmitos.py:1272-1279)
- MiTFi design (paper): 22 family-specific CMs (Leu split in two); step 1 keeps the best hit of each CM with no score cutoff; step 2 finds further copies with E <= 0.001; if a tRNA has only two interior stem-loops it looks for a 7-nt (else 9-nt) unpaired loop as anticodon loop; if none fits, the anticodon is left empty and the hit is labelled with the CM's amino acid (doi:10.1093/nar/gkr1131)
- MiTFi output (`*_tRNAout.nc`, `|`-separated, 3 lines per hit): genome start/stop (1-based), strand, model start/stop, bit score, E-value, anticodon position (-1 = none), anticodon, assigned name (col 13), model file (col 14), tophit flag, copy flag, g/l (mitos/mitfi/__init__.py:435-477)
- Flags `tophit` -> mito=2 (first-round "best hit"), `copy` -> mito=1 (second-round candidate), else 0 and dropped; hits of 10 nt or less are dropped (mitos/mitfi/__init__.py:479-484) (mitos/mitfi/__init__.py:522-523) (mitos/mitfi/__init__.py:545-547)
- Candidate sets for tRNA: round 1 = all mito==2 hits; round 2 = mito==1 hits with E <= 0.001 (mitos/scripts/runmitos.py:302-306)
- Naming: MiTFi names the tRNA from the anticodon and the genetic code ("decides based on the anticodon, and not based on the model", maintainer), so a hit found by trnP.cm can be named trnY; `trnX(---)` means no anticodon could be read and the CM's amino acid is used (https://gitlab.com/Bernt/MITOS/-/issues/49) (mitos/mitfi/__init__.py:452-468)
- The anticodon-to-amino-acid mapping runs inside the Java jar with the table given by `-code` (not inspectable here); the Python side only stores the anticodon (reverse-complemented codon object, written in lower case); L1/L2 and S1/S2 are defined as the codon families CTN/TTR and AGN/TCN (mitos/mitfi/__init__.py:98-107) (mitos/mitfi/__init__.py:452-457) (mitos/trna/__init__.py:50-95) (mitos/trna/__init__.py:158-162) (mitos/mito/__init__.py:9-32)
- Output name = `NAME[_COPY][-PART](anticodon)` in lower case, e.g. `trnM_0(cat)`; `(---)` when no anticodon; the BED score column holds the E-value; BED start is 0-based (mitos/feature/__init__.py:1065-1102) (mitos/feature/__init__.py:839-855)
- Copy/part numbers come from `_copy_part`: hits of one name sorted by E-value; a hit joins an existing copy as another part ("-a", "-b") only if its E-value is within `--fragfac` (10x) and its model range overlaps by <= `--fragovl` (20%); otherwise it starts a new copy; numbers are written only if there is more than one copy (copy) or more than one part (part). So `trnM_0(cat)` means at least two trnM-type hits exist and this one has the best E-value (mitos/mergefeature/__init__.py:576-734)
- Conflict resolution (`featureappend`): candidates are added in E-value order; a candidate is rejected into `ignored.mitos` if it is included in, or includes, an accepted feature, or overlaps one by more than `--finovl` (default 50 nt); tRNA vs rRNA may overlap by up to tRNA length - 1, and in round 1 a tRNA with E > 1e-3 overlapping an rRNA beyond that is removed (mitos/mergefeature/__init__.py:14-141) (mitos/scripts/runmitos.py:494-504) (mitos/scripts/runmitos.py:812-813)
- First-round feature order: prot, tRNA, rRNA, intron, OL, oprot, OH (mitos/scripts/runmitos.py:494)
- Round 2 (unless `--best`): remaining hits are ranked by E-value (tRNA/rRNA) or score (protein) divided by that of the best hit of the same name and appended if conflict-free (mitos/scripts/runmitos.py:685-721)
- Protein genes: `blastx -query_gencode <code> -seg no -outfmt 6 -num_alignments 1e9` per gene family against `featureProt/*.fas`, no E-value filter at BLAST level; hits are summed into per-position "quality" per reading frame, positions below `--cutoff` (default 0.5) x the maximum are trimmed, then start/stop are optimised with learned codon statistics from auxinfo.json (`--ncbicode` switches to NCBI start/stop) (mitos/update/__init__.py:540-566) (mitos/blast/__init__.py:872-958) (mitos/blast/__init__.py:1071) (mitos/blast/__init__.py:1151) (mitos/blast/__init__.py:1689) (mitos/scripts/runmitos.py:113-142)
- OH is found by BLASTN against `featureNuc/OH.fas`; OL by the covariance model OL.cm; group I/II introns by Intron_gpI.cm / Intron_gpII.cm (mitos/update/__init__.py:581-590) (mitos/mitfi/__init__.py:163-166)
- Problems report printed at the end: `missing:`, `duplicated:`, `non standard:`, `translational exceptions`, `internal stops` (mitos/scripts/runmitos.py:952-1003) (mitos/scripts/runmitos.py:1478-1503)

## Defaults that matter
- `--ncev 0.01` (fast-pass E-value for cmsearch and MiTFi) (mitos/scripts/runmitos.py:1259-1264)
- `--finovl 50`, `--maxtrnaovl 50`, `--maxrrnaovl 50` (CLI), although the function signature shows 100/10/10 (mitos/scripts/runmitos.py:1155-1161) (mitos/scripts/runmitos.py:1272-1286) (mitos/scripts/runmitos.py:51) (mitos/scripts/runmitos.py:62-63)
- `--locandgloc` is off: MiTFi/cmsearch run in local mode only (mitos/scripts/runmitos.py:1251-1257)
- `--fragfac 10`, `--fragovl 0.2` (copy/part rules); `--evalue 2` (protein: discard BLAST hits with -log(e) < 2); `--cutoff 0.5`; `--clipfac 10` (mitos/scripts/runmitos.py:1177-1228)
- Circular by default (`--linear` to switch off); `--circrot 0` -> rotations 0 and 180 degrees (mitos/scripts/runmitos.py:1087-1093) (mitos/scripts/runmitos.py:1163-1169)
- Feature order defaults `--prot 1 --trna 2 --rrna 3 --intron 4 --oril 5 --orih 6`; setting one to 0 skips that feature class, and `--orih` stays on if not set to 0 (mitos/scripts/runmitos.py:1114-1154) (mitos/scripts/runmitos.py:1355-1363)
- Reference-data path = `--refdir` + `-r`; both are needed (`-r` is a sub-directory of `--refdir`) (mitos/scripts/runmitos.py:1094-1111) (mitos/scripts/runmitos.py:1324-1334) (https://gitlab.com/Bernt/MITOS/-/issues/22)
- Genetic code: `-c <transl_table>` is mandatory; mitfiGeneticCodes contains tables 1-6, 9-16, 21-33 (no 7, 8, 17-20) (mitos/mitfi/parser/mitfiGeneticCodes:1)
- Protein start/stop statistics in auxinfo.json exist only for codes 2, 4, 5, 9, 13, 14, 24 (plus learned "*" variants); any other code falls back to code 2 for start/stop and length statistics (only a logged warning) (mitos/scripts/runmitos.py:128-142) (refseq89m/auxinfo.json:1)
- Models in refseq89m: 22 tRNA CMs trained on 5,053 (trnL1) to 10,494 (trnL2) sequences each (trnM 8,216), CLEN 67-73 (22 models: 67 x4, 68 x3, 69 x5, 70 x6, 71 x2, 72 x1, 73 x1); generic tRNA.cm NSEQ 172,419 (unused by runmitos) (refseq89m/ncRNA/trnM.cm:5) (refseq89m/ncRNA/tRNA.cm:22)

## Known bugs / issues
- MiTFi is a closed jar; the maintainer asked its author to release the source (June 2024) and no release is documented; MiTFi crashed (exit 1) on 77 of 500+ assembled mitogenomes; the maintainer's suspected cause (not confirmed) is characters other than ACGT, in particular `*` and probably IUPAC codes like Y, and he wrote that MITOS "needs a check for this" (https://gitlab.com/Bernt/MITOS/-/issues/47)
- Anticodon/name confusion: with a custom database a user got `2x trnY 2x trnN` "duplicated" and `missing: trnP trnT` because MiTFi named hits from trnP.cm/trnT.cm by anticodon as Y/N; the maintainer advises checking the anticodon (cols 11-12 of `*_tRNAout.nc`) and aligning with `cmalign`, and mentions tRNA remolding (https://gitlab.com/Bernt/MITOS/-/issues/49)
- Leu/Ser numbering (L1/L2, S1/S2) is used differently for human/primates and the rest; the reporter proposes dropping the numbers and using the anticodon; open since 2020 (https://gitlab.com/Bernt/MITOS/-/issues/15)
- Possible spurious copy suffix: "-0 suffix remains even if no duplicates are present" (reporter: probably MITOS1 only; open) (https://gitlab.com/Bernt/MITOS/-/issues/10)
- cmsearch crashes: exit -11 with Infernal 1.1.4 (fixed by 1.1.5); exit -9 on `rrnL --nohmm` in sensitive mode, which needs more than 11 GB RAM on the maintainer's machine (rRNA only) (https://gitlab.com/Bernt/MITOS/-/issues/44) (https://gitlab.com/Bernt/MITOS/-/issues/56)
- `cmrealign.str` not found (rRNA structure refinement) on inputs with many Ns (https://gitlab.com/Bernt/MITOS/-/issues/48)
- Paper text for MiTFi is internally inconsistent on overlap handling (Methods: keep the smallest E-value; Results: "selects only the one with the largest E-value" for overlaps >10 nt); MITOS2 passes `-overlap 50` instead of MiTFi's default 10 (doi:10.1093/nar/gkr1131) (mitos/mitfi/__init__.py:142)
- Custom reference databases: generation scripts live only in the branch `db-generate-scripts` (unpublished, needs HPC); custom CMs must keep the file names (trnA.cm ...); one user's CMs built from 4 species gave "missing" for all tRNAs; with a second model set MiTFi threw a `StringIndexOutOfBoundsException`, the cmout files showed only the HMM stage and trnY.cm had been built with `--noss`, cause not resolved in the thread; maintainer: data from 4 species is insufficient (https://gitlab.com/Bernt/MITOS/-/issues/19)
- Issue tracker checked 2026-10-20 (52 issues via the GitLab API, #1-#58); the ones that concern tRNA output are #10, #15, #47, #49 above, all four listed as open (https://gitlab.com/Bernt/MITOS/-/issues)

## Limitations by taxon
- Taxa that lost many tRNA genes (Cnidaria, Chaetognatha, sponges): MiTFi's forced best hit per CM produced many false positives in the original MiTFi evaluation (doi:10.1093/nar/gkr1131)
- Arthropoda: frequent D/T-arm loss (Chelicerata, Crustacea, Myriapoda); Nematoda (especially Enoplea): many tRNAs lack the T-domain, some lack D and T; Sciaroidea, Onychophora, Rotifera: truncated or incomplete tRNA sets with poor E-values; for Enoplea the MiTFi authors built nematode-specific CMs and added hits by hand (doi:10.1093/nar/gkr1131)
- Arachnida: MiTFi recovered 89.7% of the annotated tRNAs (ARWEN 82.8%, tRNAscan-SE 50.4%) (doi:10.1093/nar/gkr1131)
- refseq89m/ncRNA holds exactly the 22 metazoan tRNA models plus the generic tRNA.cm, rrnS, rrnL, OL and two intron models (directory listing 2026-10-20); no nematode-specific tRNA model is installed (mitos/mito/__init__.py:9-32)
- Our own benchmark with MITOS2 fast mode: 96.7% sensitivity and 21 false positives on 85 cnidarian/sponge/placozoan RefSeq mitogenomes (183 tRNAs), 97.3% and 3 false positives on 40 annelid RefSeq mitogenomes (880 tRNAs); the cnidarian false positives mostly come from MITOS2 and may be missing NCBI annotations 未确证 (README.md:670-676)
- Our test run 2026-10-20 (fast mode, tRNA only): NC_000931 (Platynereis dumerilii, code 5) 22/22 RefSeq tRNAs with identical boundaries; NC_006902 (Montipora cactus, code 4) trnM and trnW, both identical to RefSeq boundaries, no extra tRNA; unmodified full mode on NC_006902 added two weak false tRNAs (E 0.065 and 0.041) (mitos/scripts/runmitos.py:302-306) (mitos/scripts/runmitos.py:275-298)
- Non-metazoan mitochondria: refseq89m is the metazoan set; `refseq89f` (fungi) and `refseq89o` (Opisthokonta) exist as separate Zenodo files (https://zenodo.org/records/4284483)

## Relevance to our pipeline
- Our pipeline runs MITOS2 for tRNAs only: `runmitos_fast.py ... --prot 0 --rrna 0 --intron 0 --oril 0` (mito_trna.py:150-165). `--orih` is not set to 0, so the OH BLASTN still runs: tested 2026-10-20 with exactly these flags on NC_000931, result.bed gained 23 spurious `OH_*` lines (OH_0-a, OH_1-a ...) next to the 22 tRNAs; the tRNA lines were identical to a run with `--orih 0`, and `MITOS_NAME` ignores `OH_*`. Adding `--orih 0` would save the BLASTN and remove the spurious lines (a spurious OH accepted in round 1 could in principle block a second-copy tRNA that overlaps it by more than 50 nt; not observed).
- `scripts/runmitos_fast.py` replaces `mitfi.remove_empty` with a function that returns False, which skips the sensitive `--max`, E 0.1 re-search; this matches the analysis above (the fallback is the cause of 640 s vs 8 s on one anthozoan). In fast mode the only thresholds are the fast-pass E <= 0.01 for best hits and E <= 0.001 for extra copies.
- Because only tRNAs are searched, MITOS2's own overlap filter never sees protein or rRNA genes; a tRNA call inside a CDS or rRNA is therefore not removed by MITOS2, and `mito_trna.py` has no CDS/rRNA overlap filter either (grep-checked). Check this if a MITOS2 tRNA lies inside a PCG.
- The parser must keep `trnM_0(cat)` (several copies of one model; copy 0 = best E-value) and `trnQ(---)` (anticodon unreadable); `MITOS_NAME` already does (mito_trna.py:148-178). The name comes from the anticodon, not the model: `trnL1`/`trnL2`, `trnS1`/`trnS2` must be mapped back to L/S by amino acid.
- Boundaries: MITOS2 boundaries were identical to NCBI in 24/24 loci of our two test genomes; the README states MITOS2 gives the most exact boundaries versus NCBI, which is why boundaries are taken from MITOS2 first.
- MITOS2 tRNA anticodons depend on `-c`; pass the same `--genetic_code` as the rest of the pipeline. Non-ACGT characters (N runs, IUPAC) in the input can crash MiTFi; sanitise or catch the failure (the pipeline keeps the input tRNAs when MITOS2 fails, mito_trna.py:385-392).
- Reference data are the RefSeq-89-era set (probably July 2018, see Version checked); newly described lineages with unusual tRNAs may be missed or mis-named.
